# Дослідження операцій

Статичний сайт із матеріалами курсу «Дослідження операцій» (ФКНК, КНУ імені
Тараса Шевченка). Без збірки і без залежностей — HTML, один файл CSS і
трохи вбудованого JavaScript на сторінці анекдотів.

**Сайт:** <https://leafyff.github.io/OperationResearchSite/index.html>

## Структура

```
index.html         про курс, викладачі, перелік розділів
lectures.html      лекції (.pptx)
practice.html      практичні заняття (.pdf)
labs.html          лабораторні роботи (.pdf)
literature.html    література (.pdf)
other.html         програма курсу, програмні засоби
jokes.html         анекдоти з голосуванням
404.html           сторінка «не знайдено»
css/style.css      усі стилі
img/               графіка сайта (лис на сторінці 404)
materials/         файли матеріалів
.nojekyll          вимикає обробку Jekyll на GitHub Pages
```

## Куди класти файли

Сторінки посилаються на конкретні імена файлів. Достатньо покласти файл із
таким іменем — посилання запрацює.

| Тека | Імена файлів |
|---|---|
| `materials/lectures/` | `lecture-01.pptx` … `lecture-12.pptx` |
| `materials/practice/` | `practice-01.pdf` … `practice-09.pdf` |
| `materials/labs/` | `lab-01.pdf` … `lab-07.pdf`, проєкт — `lab-08.pdf` |
| `materials/literature/` | імена див. у `literature.html` |
| `materials/other/` | `syllabus.pdf`, `exam-questions.pdf` |

Номер завжди з двох цифр: `lab-03.pdf`, а не `lab-3.pdf`.

Якщо зручніше тримати власні імена файлів — не перейменовуйте їх, а виправте
адресу в атрибуті `href` відповідного рядка на сторінці.

## Рядки без файлів

Пункт, для якого файла ще немає, показується сірим із позначкою «буде додано»
і не є посиланням:

```html
<li><span class="row is-missing"><!-- lab-01.pdf -->
  <span class="m-num">1</span>
  <span class="m-title">Назва роботи</span>
  <span class="m-ext">буде додано</span></span></li>
```

Коли файл з’явився, перетворіть рядок на посилання — тобто замініть
`<span class="row is-missing">` на `<a class="row" href="materials/labs/lab-01.pdf">`,
закривний `</span>` на `</a>`, а «буде додано» на `pdf`:

```html
<li><a class="row" href="materials/labs/lab-01.pdf">
  <span class="m-num">1</span>
  <span class="m-title">Назва роботи</span>
  <span class="m-ext">pdf</span></a></li>
```

Щоб **додати** пункт — скопіюйте такий блок і змініть номер, назву та `href`.
Щоб **прибрати** — видаліть блок цілком.

## Що вже завантажено

- **Практичні заняття 1–6** — вступ до дослідження операцій, форми задач,
  графічний метод, симплекс-метод, двоїстість, двоїстий симплекс-метод.
- **Лабораторні 1–3** — формалізація задач, перетворення форм задач,
  графічний метод.
- **Проєкт** (лабораторна 8) — умови проєктної роботи, 20 варіантів тем.
- **Література** — 9 посібників і підручників (див. `literature.html`).
- **Анекдоти** — 13 анекдотів із голосуванням (див. `jokes.html`).

Лекції, практичні 7–9, лабораторні 4–7 та документи в розділі «Інше»
ще чекають на файли.

Назви тем лекцій усе ще взяті за типовою програмою — їх варто звірити з робочою
програмою. Теми практичних і лабораторних відповідають плану 2026 року.

## Анекдоти і лайки

Анекдоти лежать просто в розмітці `jokes.html`. Щоб додати новий, скопіюйте
будь-який блок і дайте йому наступний вільний `data-id`:

```html
<li class="joke" data-id="joke-14">
  <p class="j-setup">Питання або зачин.</p>
  <p class="j-punch">Відповідь.</p>
</li>
```

Анекдот без поділу на зачин і відповідь — це один `<p class="j-text">`.

**`data-id` не можна міняти в наявних анекдотах** — це ключ лічильника.
Змінили ключ — лічильник почався з нуля. Видалили анекдот і згодом повернули
з тим самим `data-id` — лайки повернулися разом з ним.

Порядок у розмітці — це порядок за замовчуванням. Його видно, поки не
завантажилися лічильники, і за ним шикуються анекдоти з однаковою кількістю
лайків.

### Як влаштовані лічильники

Рахує [Abacus](https://jasoncameron.dev/abacus/) — безкоштовний сервіс
лічильників без реєстрації. Ключів у коді немає: `/hit` додає одиницю,
`/get` читає значення. Налаштування — п'ять рядків на початку скрипта внизу
`jokes.html`.

Про що варто знати:

- **Лайк остаточний.** Зменшити лічильник можна лише адмінським ключем, а
  тримати такий ключ у відкритому коді сторінки немає сенсу. Тому кнопка
  після натискання блокується, і на сторінці про це сказано прямо.
- **«Один лайк» тримається на `localStorage`.** Це межа можливого без
  реєстрації користувачів: той, хто дуже хоче, проголосує ще раз з іншого
  браузера.
- **Ліміт сервісу — 30 запитів за 10 секунд з однієї адреси.** Анекдотів
  тринадцять, тобто тринадцять запитів на відкриття сторінки, тож значення
  кешуються в браузері на хвилину. Якщо з університетської мережі (спільна
  зовнішня адреса) ліміт усе одно впиратиметься, збільште `FRESH`.
- **Якщо сервіс не відповість**, сторінка покаже останні відомі числа, а як
  і їх немає — прибере кнопки й напише про це рядком. Анекдоти лишаються на
  місці в обох випадках.
- `NS` — простір імен лічильників, зараз це домен сайту. Переїдете на інший
  домен і зміните `NS` — голосування почнеться з нуля.

Якщо лічильники колись знадобиться перенести на власний бекенд, міняти треба
лише функцію `ask()` — решта скрипта про сервіс нічого не знає.

## Публікація на GitHub Pages

1. Створіть репозиторій на GitHub і залийте туди вміст цієї теки:

```bash
git init && git add . && git commit -m "Матеріали курсу" && git branch -M main && git remote add origin https://github.com/USERNAME/REPO.git && git push -u origin main
```

2. У репозиторії: **Settings → Pages**.
3. У полі **Source** оберіть **Deploy from a branch**, гілка `main`, тека `/ (root)`, натисніть **Save**.
4. Через 1–2 хвилини сайт буде за адресою `https://USERNAME.github.io/REPO/`.

Якщо назвати репозиторій `USERNAME.github.io`, адреса буде без підпапки:
`https://USERNAME.github.io/`.

**Одне уточнення для `404.html`.** GitHub Pages віддає цю сторінку за будь-якою
неіснуючою адресою, тож шляхи в ній вказані від кореня домену. Сайт лежить у
підпапці `/OperationResearchSite/`, тому всі три шляхи в цьому файлі починаються
з неї:

```
href="/OperationResearchSite/"                 (двічі: назва в шапці й посилання внизу)
src="/OperationResearchSite/img/fox-404.webp"
```

Якщо перейменувати репозиторій, замініть назву підпапки в усіх трьох місцях.
Якщо сайт переїде в корінь домену (репозиторій `USERNAME.github.io`), поверніть
`href="/"` і `src="/img/fox-404.webp"`.

Решти сторінок це не стосується — там усі шляхи відносні й працюють за
будь-якої адреси.

**Картинка на 404.** `img/fox-404.webp` — стокове зображення з pngtree. На
оригіналі був вмальований шаховий фон і водяні знаки; фон вирізано, але поверх
самого лиса водяний знак міг лишитися. Якщо потрібна чиста ліцензована
графіка — просто покладіть інший файл під тим самим іменем.

Зверніть увагу: у теці `materials/` близько 33 МБ PDF — це в межах ліміту
GitHub (рекомендовано до 1 ГБ на репозиторій), але окремі файли понад 50 МБ
git прийме лише з попередженням.

## Перегляд локально

Просто відкрийте `index.html` у браузері — цього достатньо, сервер не потрібен.
